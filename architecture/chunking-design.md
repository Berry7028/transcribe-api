# Chunking Design

OpenAI Speech to Text API にはアップロードサイズ制限があるため、大きい音声ファイルは分割して送信します。

このプロジェクトでは、できるだけ発話の途中で切らず、無音区間で分割する方針です。

## 基本方針

```text
1. 正規化後の音声ファイルサイズを確認する
2. 制限以下なら分割しない
3. 制限を超えるなら無音区間を検出する
4. 目標サイズまたは目標時間に近い無音区間を探す
5. そこでチャンクを切る
6. すべてのチャンクが制限以下になるまで繰り返す
```

## なぜ単純な時間分割にしないか

単純に 5 分ごと、10 分ごとに切ると、話している途中で音声が分断される可能性があります。

その場合、前後の文脈が失われて文字起こし精度が落ちたり、結合後の文章が不自然になったりします。

そのため、可能な限り無音区間で分割します。

## 目標チャンクサイズ

OpenAI API の上限が 25MB の場合でも、ギリギリの 25MB を狙わない方が安全です。

最初は以下のような設定にします。

```text
API 上限: 25MB
実際のチャンク目標: 20MB から 23MB 程度
```

理由:

- エンコード差分でサイズが少し変わる可能性がある
- API 側の境界条件で失敗しにくくする
- リトライ時の扱いが楽になる

## 無音検出の考え方

無音検出では以下の値を調整します。

```text
min_silence_len: どれくらい無音が続いたら無音区間とみなすか
silence_thresh: どれくらい小さい音量を無音とみなすか
keep_silence: 分割後も前後にどれくらい無音を残すか
```

最初の仮設定:

```text
min_silence_len: 700ms
silence_thresh: 音声平均音量より 16dB 低い値
keep_silence: 300ms
```

## チャンク情報として持つべきデータ

各チャンクには以下の情報を持たせます。

```json
{
  "index": 0,
  "path": "tmp/chunks/audio_000.mp3",
  "start_seconds": 0.0,
  "end_seconds": 300.0,
  "size_bytes": 12345678
}
```

この情報があると、後でレスポンスにタイムスタンプを含めたり、デバッグしたりしやすくなります。

## 無音区間が見つからない場合

無音区間が見つからない音声もあります。

その場合は以下のフォールバックを使います。

```text
1. まず無音検出のしきい値を少し緩める
2. それでも見つからなければ時間ベースで分割する
3. 時間ベース分割では、少しだけ前後を重ねる
```

前後を少し重ねることで、分割境界で単語が欠けるリスクを下げます。

## オーバーラップ

時間ベースで分割する場合、チャンクの境界に 1 秒から 2 秒程度の重なりを作る可能性があります。

ただし重ねすぎると、結合後に同じ文章が重複することがあります。

最初の実装ではオーバーラップなしでもよいです。精度が気になった段階で追加します。

## 並列処理について

チャンクごとの OpenAI API 呼び出しは、理論上は並列化できます。

ただし最初は順番に処理します。

理由:

- 実装が簡単
- レート制限に引っかかりにくい
- デバッグしやすい

後で速度が必要になったら、並列数を 2 から 3 程度に制限して実行する設計にします。
