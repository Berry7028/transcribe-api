# transcribe-api Architecture

このプロジェクトは、MP3 や動画ファイルを API に送信すると、音声を文字起こしして結果を返すバックエンドサービスです。

最初の目的は、OpenAI の Speech to Text API を使って高精度な文字起こしを行うことです。ただし OpenAI 側のアップロードサイズ制限があるため、長時間ファイルや大きいファイルは、無音区間を使って適切にチャンク分割してから文字起こしします。

この `architecture/` フォルダには、実装コードではなく、これからコードを書くための設計メモを置きます。

## 想定する技術構成

- 言語: Python
- API フレームワーク: FastAPI
- 音声・動画処理: ffmpeg
- 無音検出・チャンク分割: pydub または librosa
- 文字起こし API: OpenAI Speech to Text API
- 設定管理: `.env` と Pydantic Settings
- テスト: pytest

## このサービスがやること

1. クライアントから音声または動画ファイルを受け取る
2. 動画ファイルなら音声だけを抽出する
3. 音声形式を OpenAI API に送信しやすい形式へ整える
4. ファイルサイズが制限以下ならそのまま文字起こしする
5. ファイルサイズが制限を超える場合は無音区間でチャンク分割する
6. 各チャンクを OpenAI API に送信する
7. チャンクごとの文字起こし結果を順番に結合する
8. 全文とチャンク情報を JSON で返す

## 設計で大事にすること

- API 層と処理ロジックを分ける
- OpenAI API に依存する処理を一箇所に閉じ込める
- 後で `whisper-1` 以外のモデルに変更できるようにする
- 長時間ファイルでも扱えるようにチャンク処理を最初から設計に入れる
- 最初はシンプルな同期処理で作り、必要になったら非同期ジョブ化する
