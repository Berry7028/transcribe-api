# Processing Flow

アップロードされたファイルが文字起こし結果になるまでの流れです。

## 全体フロー

```text
1. API がファイルを受け取る
2. ファイル形式を検証する
3. tmp/uploads/ に一時保存する
4. 動画または音声を ffmpeg で正規化する
5. 正規化後の音声ファイルサイズを確認する
6. OpenAI API の上限以下ならそのまま文字起こしする
7. 上限を超えるならチャンク分割する
8. チャンクごとに文字起こしする
9. チャンク結果を結合する
10. 一時ファイルを削除する
11. JSON レスポンスを返す
```

## 1. API がファイルを受け取る

`app/api/routes/transcription.py` が担当します。

この時点では、ファイルを受け取って `transcription_service.py` に渡すだけにします。

## 2. ファイル形式を検証する

対応する拡張子だけ許可します。

想定する対応形式:

- mp3
- mp4
- mpeg
- mpga
- m4a
- wav
- webm

## 3. 一時保存する

アップロードされたファイルは一度 `tmp/uploads/` に保存します。

API の `UploadFile` をそのまま複数の処理に渡すより、ローカルパスとして扱える方が ffmpeg やサイズチェックと相性が良いです。

## 4. ffmpeg で正規化する

動画ファイルでも音声ファイルでも、内部処理では扱いやすい音声形式にそろえます。

最初は以下のどちらかに寄せる想定です。

```text
mp3
wav
```

OpenAI API へ送信するサイズを考えると、最終的には `mp3` や `m4a` のような圧縮形式が扱いやすいです。

## 5. ファイルサイズを確認する

正規化後の音声ファイルが OpenAI API のアップロード制限以下か確認します。

制限より小さい場合はチャンク分割しません。

## 6. そのまま文字起こし

小さいファイルは `openai_service.py` に渡して、そのまま文字起こしします。

## 7. チャンク分割

大きいファイルは `chunk_service.py` で分割します。

単純に時間で切るのではなく、できるだけ無音区間で切る方針です。

## 8. チャンクごとに文字起こし

各チャンクを順番に OpenAI API に送信します。

最初は順番に処理します。あとで高速化したくなったら並列処理を検討します。

## 9. 結果を結合する

`merge_service.py` が担当します。

チャンクの順番通りにテキストを結合し、必要なら開始秒・終了秒などのメタデータもまとめます。

## 10. 一時ファイルを削除する

処理が成功しても失敗しても、不要な一時ファイルは削除します。

最初は手動で削除処理を書き、後でバックグラウンドクリーンアップを追加してもよいです。
